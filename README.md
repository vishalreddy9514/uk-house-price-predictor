# UK House Price Predictor

An end-to-end ML project: synthetic-but-realistic UK housing data → feature
engineering → model comparison (Linear Regression baseline vs XGBoost) →
FastAPI backend → Streamlit frontend → Dockerised and deployable.

## Results

| Model | Validation MAE | Validation R² |
|---|---|---|
| Linear Regression (baseline) | £31,950 | 0.933 |
| **XGBoost (selected)** | **£21,249** | **0.978** |

Final held-out test performance: **MAE £21,719, R² 0.974**.

## Why these feature engineering choices

- `property_age` (derived from `year_built`) is more predictive than raw
  year — models generalise better from "how old" than an arbitrary year number.
- `sqft_per_bedroom` flags unusually cramped or spacious properties relative
  to their bedroom count, which raw sqft or bedroom count alone can't capture.
- Categorical features (`region`, `property_type`) are one-hot encoded;
  numeric features are standardised — both inside a single sklearn
  `Pipeline` + `ColumnTransformer`, so there's no risk of preprocessing
  mismatch between training and inference.

## Running locally

```bash
# 1. Create a virtual environment
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate the dataset
python src/generate_data.py

# 4. Train the model (prints model comparison, saves models/model.joblib)
python src/train.py

# 5. Start the API (terminal 1)
uvicorn api.main:app --reload --port 8000
# Visit http://localhost:8000/docs to try it interactively

# 6. Start the frontend (terminal 2, API must still be running)
streamlit run app/streamlit_app.py
# Visit http://localhost:8501
```

## Using REAL UK data instead of synthetic

Download HM Land Registry Price Paid Data (free, no auth needed):
https://www.gov.uk/government/statistical-data-sets/price-paid-data-downloads

It won't have every column this project uses (e.g. `crime_score`,
`dist_to_station_km`) — you'll need to enrich it, which is itself a good
thing to describe in an interview:
- Crime data: [police.uk data downloads](https://data.police.uk/data/) (free, by force/area)
- Distance to station: [Ordnance Survey](https://www.ordnancesurvey.co.uk/products) or
  OpenStreetMap station coordinates + a distance calculation
- Once reshaped to match the columns in `data/uk_housing.csv`, `train.py`
  and everything downstream works unchanged.

## Deployment (both free tiers)

**Backend (FastAPI) → Render:**
1. Push this repo to GitHub.
2. On [render.com](https://render.com), New → Web Service → connect your repo.
3. Render auto-detects the `Dockerfile`. Set the port to `8000`.
4. Deploy. You'll get a URL like `https://your-app.onrender.com`.
5. Test it: `https://your-app.onrender.com/docs`

**Frontend (Streamlit) → Streamlit Community Cloud:**
1. On [share.streamlit.io](https://share.streamlit.io), New app → connect
   the same GitHub repo, set main file to `app/streamlit_app.py`.
2. In the app's settings → Secrets, add:
   ```
   API_URL = "https://your-app.onrender.com"
   ```
3. Deploy. You now have a live, clickable demo link for your CV.

*(Why two separate free services instead of one: Render's free tier is
built for backend APIs; Streamlit Community Cloud is purpose-built and
zero-config for Streamlit apps specifically — pairing them is the fastest
path to a live demo with zero cost.)*

**Alternative: Azure App Service** (worth doing if targeting UK roles —
Azure appears constantly in job specs). Push the same Docker image to
Azure Container Registry and deploy via App Service for Containers; the
Dockerfile needs no changes.
